Intra-session purchase propensity model

Case objective: build a prototype model that estimates the probability that a session will end in a transaction, then explain how the score could be activated in marketing and personalization use cases.

Executive summary

The dataset contains session-level anonymized e-commerce session data for roughly one month. The target is rare: only about 1.4% of sessions end in a transaction.

Because of this imbalance, a plain accuracy metric would be misleading. A model that predicts "no transaction" for every session would look accurate but would have no business value. The useful question is whether the model can rank sessions by purchase propensity so that the highest-scored sessions convert far above the site average.

I evaluate the prototype mainly through ranking metrics and lift:

  • ROC-AUC and PR-AUC for overall ranking quality.
  • Conversion rate and lift in the top 1%, 5%, 10% and 20% of scored sessions.
  • Recall captured inside those top-ranked segments.

I also compare two scoring moments:

  • Entry model: can be scored at landing/session start using traffic, device, geo, time and landing page features.
  • Intra-session model: uses additional page-path and timing signals observed after the user has browsed further into the session.

This distinction matters commercially: later scoring gives stronger signals, but earlier scoring gives more time to intervene.

Deduplication rule

There are a small number of repeated sessId values. For a session-level model I keep one row per session:

  • Sort by sessId and visitStartTime.
  • Keep the first observed row for descriptive/session features.
  • Set the label to max(transaction) within the duplicated session.

This preserves the fact that a session converted if any duplicated record indicates a conversion, while keeping the modelling unit at one row per session.

def conversion_table(data: pd.DataFrame, column: str, min_sessions: int = 100, top_n: int = 10):
    table = (
        data.groupby(column, dropna=False)
        .agg(
            sessions=("transaction", "size"),
            transactions=("transaction", "sum"),
            conversion_rate=("transaction", "mean"),
        )
        .query("sessions >= @min_sessions")
        .sort_values("conversion_rate", ascending=False)
        .head(top_n)
    )
    return table

4. Feature strategy

I build two feature sets because "intra-session" can mean different scoring moments.

Entry model: can be scored near the beginning of a session. It uses traffic source, device, browser, geography, time, landing page and visitor/session history.

Intra-session model: adds second and third page information plus timing signals. This should only be used once those events are observed. It is a stronger signal, but it cannot be used at the very first page view.

I intentionally exclude raw identifiers (userId, sessId) and raw timestamps from the model. The timestamp is used only to create a temporal train/test split.

model_df = df.copy()

for col in ["hitsTimeSecondPage", "hitsTimeThirdPage"]:
    values = pd.to_numeric(model_df[col], errors="coerce")
    model_df[f"log_{col}"] = np.where(
        values.notna() & (values >= 0),
        np.log1p(values),
        -1.0,
    )

# Reduces the impact of very high sessionNumber values.
model_df["sessionNumber_log"] = np.log1p(
    pd.to_numeric(model_df["sessionNumber"], errors="coerce")
)
# Transform hour and day of the week into cyclic variables.
# Helps the model recognize that 23h and 0h are close, rather than being treated as extreme values.
model_df["hour_sin"] = np.sin(2 * np.pi * model_df["hour"] / 24)
model_df["hour_cos"] = np.cos(2 * np.pi * model_df["hour"] / 24)

# The data guide says weekday is 0-6, but the data contains 1-7.
# I keep the observed encoding and assume weekend days are 1 and 7.
model_df["weekday_sin"] = np.sin(2 * np.pi * model_df["weekday"] / 7)
model_df["weekday_cos"] = np.cos(2 * np.pi * model_df["weekday"] / 7)
model_df["is_weekend"] = model_df["weekday"].isin([1, 7]).astype(int)

6. Modelling approach

I use a regularized logistic regression with one-hot encoding:

  • It handles sparse, high-cardinality categorical features well.
  • It is fast and reliable for a prototype.
  • Coefficients give directional interpretability.
  • class_weight="balanced" helps the model learn from the rare positive class.

Important: with class weighting, the output should be treated mainly as a propensity score for ranking, not as a perfectly calibrated purchase probability. If exact probabilities are needed in production, I would add probability calibration on a validation set.

def make_one_hot_encoder(min_frequency=20):
    params = {"handle_unknown": "ignore"}
    signature = inspect.signature(OneHotEncoder).parameters

    if "sparse_output" in signature:
        params["sparse_output"] = True
    else:
        params["sparse"] = True

    if "min_frequency" in signature:
        params["min_frequency"] = min_frequency

    return OneHotEncoder(**params)


def build_pipeline(feature_cols):
    feature_frame = model_df[feature_cols]
    categorical_cols = feature_frame.select_dtypes(
        include=["object", "string", "category"]
    ).columns.tolist()
    numeric_cols = [c for c in feature_cols if c not in categorical_cols]

    categorical_pipeline = Pipeline(
        steps=[
            ("imputer", SimpleImputer(strategy="constant", fill_value="__missing__")),
            ("onehot", make_one_hot_encoder(min_frequency=20)),
        ]
    )

    numeric_pipeline = Pipeline(
        steps=[("imputer", SimpleImputer(strategy="median"))]
    )

    preprocess = ColumnTransformer(
        transformers=[
            ("categorical", categorical_pipeline, categorical_cols),
            ("numeric", numeric_pipeline, numeric_cols),
        ],
        remainder="drop",
    )

    classifier = LogisticRegression(
        max_iter=2000,
        class_weight="balanced",
        solver="liblinear",
        random_state=42,
    )

    return Pipeline(
        steps=[
            ("preprocess", preprocess),
            ("classifier", classifier),
        ]
    )
def lift_table(y_true, scores, shares=(0.01, 0.05, 0.10, 0.20)):
    y_true = pd.Series(y_true).reset_index(drop=True)
    scores = pd.Series(scores).reset_index(drop=True)
    base_rate = y_true.mean()

    rows = []
    order = scores.sort_values(ascending=False).index

    for share in shares:
        n = max(1, int(len(scores) * share))
        selected = order[:n]
        selected_y = y_true.iloc[selected]
        conversion_rate = selected_y.mean()
        conversions_captured = int(selected_y.sum())
        rows.append(
            {
                "top_share": share,
                "sessions": n,
                "conversion_rate": conversion_rate,
                "lift_vs_average": conversion_rate / base_rate,
                "conversions_captured": conversions_captured,
                "recall": conversions_captured / max(1, int(y_true.sum())),
            }
        )

    return pd.DataFrame(rows)


def evaluate_model(model_name, feature_cols):
    X_train = model_df.loc[train_mask, feature_cols]
    y_train = model_df.loc[train_mask, target].astype(int)
    X_test = model_df.loc[test_mask, feature_cols]
    y_test = model_df.loc[test_mask, target].astype(int)

    model = build_pipeline(feature_cols)
    model.fit(X_train, y_train)
    scores = model.predict_proba(X_test)[:, 1]

    metrics = {
        "model": model_name,
        "roc_auc": roc_auc_score(y_test, scores),
        "pr_auc": average_precision_score(y_test, scores),
        "brier_score": brier_score_loss(y_test, scores),
        "test_conversion_rate": y_test.mean(),
        "test_sessions": len(y_test),
        "test_transactions": int(y_test.sum()),
    }

    return {
        "model_name": model_name,
        "model": model,
        "features": feature_cols,
        "scores": scores,
        "y_test": y_test.reset_index(drop=True),
        "metrics": metrics,
        "lift": lift_table(y_test, scores).assign(model=model_name),
    }

7. Ranking performance and lift

The business value is visible in the top-scored segments. If the top 5% of sessions convert many times above average, the client can prioritize those sessions for activation.

def format_lift(table):
    formatted = table.copy()
    formatted["top_share"] = formatted["top_share"].map(lambda x: f"Top {x:.0%}")
    formatted["conversion_rate"] = formatted["conversion_rate"].map(lambda x: f"{x:.2%}")
    formatted["lift_vs_average"] = formatted["lift_vs_average"].map(lambda x: f"{x:.1f}x")
    formatted["recall"] = formatted["recall"].map(lambda x: f"{x:.1%}")
    return formatted[
        [
            "model",
            "top_share",
            "sessions",
            "conversion_rate",
            "lift_vs_average",
            "conversions_captured",
            "recall",
        ]
    ]

def score_deciles(result):
    scored = pd.DataFrame(
        {
            "score": result["scores"],
            "transaction": result["y_test"].values,
        }
    )
    scored["decile"] = pd.qcut(
        scored["score"].rank(method="first"),
        q=10,
        labels=False,
    )
    deciles = (
        scored.groupby("decile")
        .agg(
            sessions=("transaction", "size"),
            conversion_rate=("transaction", "mean"),
            avg_score=("score", "mean"),
            transactions=("transaction", "sum"),
        )
        .reset_index()
    )
    deciles["decile"] = deciles["decile"] + 1
    deciles["propensity_band"] = deciles["decile"].map(
        lambda x: "highest" if x == 10 else ("lowest" if x == 1 else "middle")
    )
    return deciles

8. Model interpretation

Coefficients are useful for directional interpretation, not causal claims. Positive coefficients increase the score relative to the model baseline; negative coefficients reduce it.

def coefficient_table(result, n=15):
    model = result["model"]
    feature_names = model.named_steps["preprocess"].get_feature_names_out()
    coefficients = model.named_steps["classifier"].coef_.ravel()

    coef_df = (
        pd.DataFrame({"feature": feature_names, "coefficient": coefficients})
        .sort_values("coefficient", ascending=False)
        .reset_index(drop=True)
    )

    return coef_df.head(n), coef_df.tail(n).sort_values("coefficient")

9. How the score could be activated

The model output should become an actionable segment, not just an offline prediction.

Activation idea 1: high-intent remarketing

  • Score sessions during or shortly after the visit.
  • Build a "high propensity but no purchase" audience.
  • Activate that audience in Google Ads / Display & Video 360 with more aggressive remarketing bids or budget allocation.

Activation idea 2: onsite personalization

  • For high-propensity sessions, reduce friction: highlight checkout, shipping information, product availability, or support.
  • For medium-propensity sessions, use product recommendations or category nudges.
  • Avoid over-incentivizing users who are already likely to buy unless an incrementality test proves value.

Activation idea 3: media efficiency

  • Use lower bids or suppression rules for low-propensity audiences.
  • Reallocate spend toward users with higher expected conversion value.
  • Evaluate with holdout tests using conversion rate, CPA, ROAS and incremental revenue.

10. Limitations and next steps

Prototype limitations

  • The dataset covers only about one month.
  • The public demo dataset does not provide all commercial variables, such as margin, stock, promotion exposure or media cost.
  • The intra-session model uses second and third page information, so it must be scored only after those events are observed.
  • Scores are optimized for ranking and should be calibrated before being treated as exact probabilities.
  • A production solution would need privacy/consent checks, latency requirements, monitoring and retraining.

Next steps

  • Add richer user history, product/category signals and transaction value.
  • Calibrate probabilities on a validation period.
  • Test the model in a controlled experiment or holdout campaign.
  • Move from propensity modelling to uplift modelling if the business question becomes "which users will convert because of an intervention?"
